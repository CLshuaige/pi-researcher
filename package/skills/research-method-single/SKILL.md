# 直接生成方法设计

读取项目已有材料，在当前会话中直接形成方法设计并保存结果。只做一次综合生成，不启动 subagent，不模拟 Planner、Critic、Formatter，不进行多轮辩论或单独的格式化阶段。用户明确要求多角色迭代时使用 `research-method`。

## 阅读已有材料

使用用户指定的项目目录；未指定时使用当前 Pi 会话的工作目录，开始时说明采用的目录。不要求任何固定输入文件名、研究目录结构或预先初始化工作区。

递归发现项目目录及子目录中的 Markdown（`.md`、`.markdown`）和 JSON（`.json`），先查看路径、标题、摘要或顶层字段，再读取所有可能有用的内容，识别研究任务、假说、文献、知识、已有方法、实验结果、负结果和资源约束；相关 JSONL 材料也可按需读取。

目录约定只约束新产物，材料发现和读取仍覆盖整个项目，不限于本阶段或其他阶段目录；旧目录、用户自定义目录中的相关材料同样可用。发现相关 PDF、LaTeX、代码、数据说明或运行记录时，也按需读取，不因扩展名不同而忽略证据。

- 用户指定的材料优先读取；包含项目中被 Git 忽略的研究材料，发现材料不能只依赖默认遵守 Git 忽略规则的文件列表；通常跳过 `.git`、依赖、缓存和工具内部运行记录。
- JSON 应解析其结构，按相关对象、数组和字段提取假说、配置、数据说明、指标、资源及既有结果，保留数值单位和出处；引用时记录文件及 JSON 字段路径或数组位置。解析失败时说明错误，不把不可读等同于没有证据。
- 材料较多时分批读取；长 Markdown 按章节、大 JSON 按对象或数组片段、JSONL 按行处理。记录采用的文件及位置、跳过原因和未能读取的材料，不将路径列表或截断内容当成已读全文。
- 假说阶段的主产物为 `hypothesis.md`，结构化配套为 `hypothesis.json`；同时识别其他文件中的相关假说，不以历史文件名限制输入。Markdown 含 `[SELECTED]` 或 JSON 有 `selected_index` 等选择信息时，结合本次请求理解主要目标及替代解释。
- 用户直接给出的目标、假说和约束同样有效。没有独立假说文件时，可围绕明确的研究问题设计方法；不能确定项目范围、研究目标或待检验方向时先询问，不自行编造任务或创建成果。
- 研究资源约束取自本次请求和适用项目材料，注明出处；用户明确更新的条件优先。区分当前有效约束、历史预算和说明性示例，后两者不自动成为本次限制。未提供的条件标为未知，估计值注明依据，不预设实验周期、硬件或计算预算。未知条件会改变方案选择时再询问，否则给出条件性设计与缺口。
- 旧方案与实验记录作为背景理解，不自动当成本次已完成的工作。默认只分析已有材料，不联网检索、不安装环境、不实现代码或运行实验。

## 直接设计

结合目标、假说、已有证据和实际资源，直接给出一份连贯的方法设计。方案应说明怎样的实验或观察能回答研究问题，不要求额外评分、评审或批准。步骤数量和复杂度由任务决定，不机械套用固定模板。

方法应覆盖：

- 问题与假说：本方法要回答什么，实验与目标如何对应，哪些结果支持、反对或无法区分现有解释。
- 科学设计：必要的基线、对照、变量、测量指标及比较规则。按领域考虑数据划分、泄漏、重复或随机种子、误差来源和统计判断，不强制所有研究采用机器学习实验形式。
- 执行步骤：每步说明目的、输入、操作、依赖、预期产物和可判断的完成条件，并给出执行顺序。优先安排能区分关键解释的验证，不因节省资源而删去必要对照。
- 资源与运行范围：已有数据、代码、工具和环境的位置，已知运行方式、允许修改的范围、资源需求、预算和停止条件。复用适用的已有环境；未知命令、数据访问或资源条件如实标明，不编造可运行性。
- 人工参与：确需人工标注、访谈、主观评价或手工实验时，说明所需人员、操作及预期产物；普通自动化工作与人工任务分开描述，不把分工声明当作任务已完成。
- 验收与解释：如何确认步骤正确执行、保存哪些证据、如何解释结果。区分执行成功与假说获得支持，负结果也可以是正确完成实验后的有效结果；区分探索和最终验证。
- 风险与缺口：关键失败风险、缺失资源、估计的依据及仍需确认的条件。说明可行的简化及其解释边界，不保证假说成立。

引用已有材料时标明文件与章节、段落或 JSON 字段位置，区分原始观察、已有解释和本次推断。资源不足时交付受限但明确的方法及缺口，不把模拟试运行或设计文本称为真实实验结果。

## 保存与返回

用户明确指定输出位置时遵循该位置；否则主会话在项目根目录下创建 `method/`，本次成果目录默认即该目录。单会话与多角色版本共用这一阶段目录。已有成果时，只有明确续写才更新原目录；独立新任务使用 `method/<run-name>/` 中未占用的目录，保留历史。

相对输出路径以项目根目录为基准；技能参考和脚本以本技能安装目录为基准，成果不得写入安装目录。被 `research_delegate` 委派时只在分配目录内保存本阶段产物，由主会话读取并整合到上述阶段目录；材料发现仍以运行时给出的项目根目录为准。

在本次成果目录保存阶段主产物 `method.md`。无需创建逐轮讨论文件、Formatter 产物或交接文件。

`method.md` 包含研究目标、假说来源、阅读与采用的材料范围、上述完整方法、资源约束和未解决问题。材料路径应可被后续执行者正确定位；采用相对路径时明确基准目录。

向用户返回简短工作小结：采用了哪些材料、形成了什么方法、主要步骤和待确认条件，并提供 `method.md` 的实际产物地址。用户另有结构化输出要求时再生成配套 `method.json`，不默认增加复杂协议。

用户要求继续实验时，将完整 `method.md` 及所需材料交给 `research-experiment`。若后续采用 engine，按 [engine 接入与恢复](../../docs/engine.md) 在分配的实验目录准备 `method.md`；设计阶段不自动调用 `engine_start`，也不生成或覆盖 engine 的计划与进度文件。仅在用户要求或已有工作流需要时继续执行阶段。
