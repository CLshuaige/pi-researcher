# 直接生成研究评审

在当前会话读取已有研究材料，直接形成评审并保存为 **`review.md`**。只做一次综合评审，不启动子代理、不模拟多角色讨论、不安排修订或复审循环。需要独立新会话评审时使用 `research-review`。

本技能可独立使用或与其他技能自由组合，不要求先生成报告、完成固定阶段或初始化研究工作区。评审基于实际材料与证据，不默认认可作者解释；单会话评审不声称已实现上下文隔离。

## 读取已有材料

用户明确给出工作目录时使用该目录，否则使用当前 Pi 会话的工作目录，并说明采用的目录。无需用户逐个指定输入文件，也不要求固定目录结构或任务、方法、结果文件名。

递归发现工作目录及子目录中的 Markdown（`.md`、`.markdown`）、JSON（`.json`）及相关 JSONL、PDF、LaTeX、图表和运行记录。先查看路径、标题、摘要或顶层字段，再按内容判断并读取可能有用的研究目标、假说、方法、综述、结果和原始证据。

- 包含项目中被 Git 忽略的研究材料，通常跳过 `.git`、依赖、缓存和工具内部记录。旧评审仅在用户要求比较或核查修改时作为历史参考，不替代本次判断。阶段目录只约束新产物，材料读取仍覆盖整个项目及旧目录、自定义目录，不限于 `review/` 或其他阶段目录；发现材料不能只依赖默认遵守 Git 忽略规则的文件列表。
- 发现与本次评审相关的 **`report.pdf`** 时必须实际读取全文。可直接使用 PDF 工具，或从原 PDF 提取带页码的全文并按需渲染图表页；提取件写在本次成果目录，记录原 PDF 路径及读取范围。可用 Poppler 时用 `pdfinfo` 确认总页数、`pdftotext` 提取正文、`pdftoppm` 渲染所需页面，不能只读首页或摘要。
- **没有 report.pdf 时正常继续**，直接评审已有 Markdown、JSON、LaTeX 等材料，不因此扣分、要求生成 PDF 或调用前置技能。已有相关 PDF 却无法读取时说明读取障碍；可交付对其他材料的有限评审，但不得声称已完成该 PDF 的全文核验。只有全文提取而未查看图像时，明确未完成图表视觉检查。
- JSON 按实际结构读取相关对象、数组和字段，保留数值、单位和出处。长 Markdown 按章节、大 JSON 按片段、JSONL 按行分批处理；记录实际阅读范围、无法读取及未核验的部分，不把路径列表或截断内容当成已读全文。
- 根据本次请求与材料确定评审对象。多个版本结合内容和来源判断，不仅按修改时间选择；仍无法确定对象时再澄清。完全没有可评审材料时说明缺口，不编造审稿结果。

## 直接评审

按对象的实际目标评估主张与证据是否相称，重点判断创新性、技术质量、清晰度与意义。方案按方案评审，综述按综述评审，不要求所有成果都包含已完成的实验。

- **研究报告或方法方案：** 检查目标、假说、方法、结果和结论的对应关系；对照、基线和比较条件是否公平；按领域检查数据划分、泄漏、混杂、指标、重复性、不确定性和替代解释。报告宣称已完成实验时，按需核查实际指标、代码与运行记录；代码或程序退出成功不能替代结果证据，未重跑时不声称复现。
- **文献综述：** 检查主题边界、代表性、引用是否支持主张、不同研究是否可比、反证和局限是否保留，以及综合结论是否超出原始证据。系统综述按其自述协议检查检索和筛选，叙述性综述不强制套用系统综述要求；未做额外检索时不声称覆盖所有最新成果。
- **表达与证据：** 核查关键引用、图表、数值与结论是否一致，区分事实、作者解释和本次推断。负结果和失败也可以是有效成果，不为支持假说而忽略它们。

每项实质问题写明具体位置、发现、证据或已查范围、影响、最小修正及可判断的验收条件。用“重大问题”“次要问题”“可选建议”区分影响程度；明确区分“材料未报告”“当前无法核验”和“已有证据确认的问题”，不能把缺失材料说成确定错误。

反馈可要求补证、重分析、缩小结论或修正文案，不一律追加实验。默认只检查已有材料，不联网检索、安装依赖、运行实验、修改被评对象或自动实施反馈。

## 保存与返回

用户明确指定输出位置时遵循该位置；否则主会话在项目根目录下创建 `review/`，本次成果目录默认即该目录。单会话与独立评审版本共用这一阶段目录。已有成果时，只有明确续写才更新原目录；独立新任务使用 `review/<run-name>/` 中未占用的目录，保留历史。

相对输出路径以项目根目录为基准；技能参考和脚本以本技能安装目录为基准，成果不得写入安装目录。

直接在本次成果目录写入 **`review.md`**。被 `research_delegate` 委派时遵守分配目录和只读工具边界，由主会话将返回内容保存到阶段目录。

默认简体中文，按以下内容组织同一份 Markdown：

1. **对象与阅读范围：** 工作目录、实际采用文件及位置、PDF 阅读情况、无法访问或未核验部分。
2. **摘要：** 用 2–3 句话准确概括研究问题、方法、贡献与结论。
3. **优势：** 列出有依据的优点，关联章节或证据位置。
4. **不足与修正建议：** 按影响程度列出具体问题及其依据、影响、修正和验收条件。
5. **作者问题：** 提出能澄清关键缺口、影响判断的问题。
6. **整体评分：** 1–10 分并说明理由；材料不足以合理评价时写“未评分”及原因。
7. **置信度：** 1–5 分并说明领域把握、证据覆盖与核验深度，和整体评分分开判断。
8. **接收建议：** Strong Accept / Accept / Borderline / Reject / Strong Reject 之一；无法合理判断时写 Not Assessed。属于本次模拟学术评价，不代表实际会议录用。建议、评分与重大问题应相称。

优缺点和作者问题的数量由实际材料决定，不凑数。无需生成 context、输入指纹清单、review.json、交接 JSON 或逐轮记录，也不依赖 research-review 的脚本或协议。用户另有结构化输出要求时再提供配套数据。

完成后返回简短评审结论、主要问题、核验限制和 **`review.md` 的实际路径**。保存后结束，不自动转入改稿、实验或下一轮评审。
