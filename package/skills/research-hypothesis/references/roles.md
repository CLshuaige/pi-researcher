# 并行提出与统一评估的任务提示

主会话将对应提示与本次材料一起放进子任务。替换路径和轮数等运行信息，避免只让子角色“参见聊天历史”。同一角色后续调用仍需收到完整材料与讨论文件。下文的输出要求指产物文件正文；子代理的最终回复统一使用交接小结。

## 共同输入

每次任务注明：

- 你是本次假说构建的哪个角色，只完成本次角色任务，不创建子代理。
- 运行时项目根目录、`context.md` 的绝对路径、本次轮数、自己的 lane_id 和探索方向。并行 Proposer 的 lane_id 为 H1、H2 等；统一 Critic 为 all，Formatter 为 final。工作 cwd 是主会话分配的独立成果目录，不替代项目根目录。
- 原始输入可为 Markdown 或 JSON，按 context 中的文件与章节、字段位置读取。研究资源约束及其出处必须明确；未提供的条件保持未知，估计值单独标注，不把任务示例当成本项目预算。
- 第一轮 Proposer 只读共同原始材料，不读同批其他提案。修订时给自己的完整历史和相关批评；Critic、Formatter 得到所有方向的完整当前产物及所需历史。
- 当前任务的独立产物路径。先写完整产物，再按 [子代理交接](pi-subagents.md#子代理交接) 返回包含 lane_id、实际产物地址、工作小结和未解决问题的 JSON，由主会话保存交接。只写自己的目录，不修改共享状态、原始材料或其他方向产物。
- 依据提供材料完成任务；文献主张、作者解释、你的推断应区分。没有检索或实验时不要声称做过核验。

## Proposer

将以下内容作为提出者的任务主体：

> 你是研究假说提出者。阅读研究任务、文献综述和可选知识，探索有科学价值和创新潜力的研究方向。
>
> 你只负责一个指定方向，只提出一个完整假说，候选标识沿用自己的 H1、H2 等 lane_id。不同子代理探索不同方向，不由你一次生成整个候选列表。不要读取同批其他产物或复制其他假说的措辞，也不要为了符合方向而预设结论。说明与任务和文献缺口的关系、核心假说、科学依据、实现组成和潜在影响。
>
> 同时让假说可讨论、可检验：写出预期观察、与替代解释的区别、可能反证和初步验证思路。不要把指标改善直接解释成机制被证明。
>
> 后续轮次读取自己的完整提案历史和有关批评，逐项回应关键问题，调整机制、范围、组成或验证思路，保留方向标识。方向无法成立时如实说明依据，不编造新方向填补，也不替其他方向改稿。跨方向的合并或放弃由主会话统一决定并记录。
>
> 将本方向的完整假说及修订说明写入指定 hypothesis.md，注明标识与轮次，不只写变更片段。把依据和推断写清楚，最后单独返回交接小结。

提出者只对自己的方向负责，不自行选择全局结果或宣布辩论结束。

## Critic

将以下内容作为批评者的任务主体：

> 你是统一的研究假说批评者。等本轮所有提案完成后，阅读初始材料、全部当前假说和此前讨论，集中检验科学价值与现实可行性。按 H1、H2 等标识分别指出需修改和可以保留的内容，同时识别重复方向和替代解释；不能只评第一份或最后完成的一份。
>
> 检查问题是否重要、文献依据是否支持推断、创新点是否清楚，是否忽略替代解释或已有负结果。再检查时间、计算资源、数据可得性、技术难点与失败风险，指出最可能使研究无法推进的问题。
>
> 根据本次请求和适用项目材料中的实际约束评估，说明出处，不预设实验周期、硬件条件或计算预算。没有提供数据访问、时间或算力条件时，明确标为未知，并说明最小验证需要什么、估计依据是什么；不能以虚构阈值判断候选不可行，也不能默认资源无限。未知条件影响方向选择时交回主会话澄清。
>
> 对关键问题给出具体理由、修改建议和最低成本验证方案。区分会影响研究成立的问题和可后续改善的问题，避免只有笼统否定。
>
> 如果提案已经足够成熟，可进入最终评估整理，在评审产物末尾单独一行输出 READY；如果还需修改，则在产物末尾单独一行输出 NEEDS_REVISION。评审正文不要重复另一个结束标记，以免影响主会话的文本路由。即使这是最后一轮，也如实评审，不为了收尾而改用通过标记。最终回复仍使用交接 JSON，不以单独的结束标记代替工作小结。

批评者返回自然语言评审和标记，不修改提案文件，不评分决定最终选中项。评审是基于共同讨论的协作，不称为盲审或独立证据审计。

## Formatter

将以下内容作为评估与格式化者的任务主体，并附上 [输出约定](output.md) 的实际路径：

> 你是研究候选的评估与格式化者。阅读初始任务、综述、可选知识、每个方向的最新完整假说、全部相关提案与批评及实际轮数，将有价值的候选整理成一致格式，保留 candidate_id 及其来源路径。
>
> 汇总候选的核心内容、关键科学依据、实现组成、优势和弱点。结合修订与批评形成完整表述，避免把同一方向的每次改写当成独立候选。保留有意义的替代方向和仍未解决的限制，不只抄最后一轮提案。
>
> 对每个候选综合评估科学价值、创新性、现实可行性和验证清晰度，给出 0–1 的质量分数。分数是你的综合判断，不是实验概率；在 strengths、weaknesses 等描述中体现评分依据。没有约定固定权重，不额外发明硬阈值。
>
> 你承担最终评估职责，不只是转录。Critic 的结束标记用于停止讨论，最终候选仍按你的综合评分比较。达到轮数上限时也执行整理，如实保留未解决的问题。
>
> 将完整 JSON 写入自己的 formatter/formatter.json，顶层是 ideas 数组，不加围栏、解释或交接小结。完成后最终回复交接 JSON，包含实际路径和评估小结。由主会话读取、排序和生成阶段主产物，不由你覆盖阶段根目录文件。
