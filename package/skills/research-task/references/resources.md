# 资源判断与共享运行

使用本 Skill 的 `scripts/probe-environment.mjs` 获取当前进程的 CPU、负载、内存、磁盘和 GPU 快照。实验 Skill 复用同一脚本，不维护另一套探测逻辑。脚本只读取环境，不安装驱动、不分配 GPU、不占用显存、不运行压力测试。

## 在什么时机判断

- 任务解析：计算量或设备要求可能影响研究方向时探测，判断能否开展、哪些条件未知。task.md 只保留相关结论、观测时间与资源约束。
- 实验执行：在实验子进程内重新探测。主会话看到的设备可能未授权给子进程；之前的空闲量也可能已被其他任务使用。昂贵阶段开始前、内存不足或设备忙时再检查，不做高频轮询。

## 如何使用结果

- CPU：结合当前可用并行度、负载和可读的 cgroup 配额估计预算，不直接把逻辑核数设为线程数。避免多进程与每进程 BLAS/OpenMP 线程同时扩张。先用有限并行验证，按任务需要再调整。
- 内存与磁盘：考虑可见额度、已有占用和余量。没有读到配额不代表没有限制；保留开销余量，先估计数据、模型、checkpoint 和中间文件规模。
- GPU：区分设备可访问、瞬时空闲显存、利用率与框架真实可运行。查询失败或不支持的指标为未知，不能当作空闲。没有必要时使用 CPU；需要 GPU 时优先少量设备和小规模真实检查，避免默认多卡或占满显存。
- 当前负载不是预留：空闲显存可能已被其他作业计划使用，低利用率的卡也可能驻留着模型；利用率本身不能确定作业归属。遵守宿主分配和任务预算；发现竞争时减少批量/并行度、等待或交接，不停止其他人的进程、不重置设备、不改变其计算模式。
- 显式设备范围是上限：自动检测只是提供选择空间，不是使用全部资源的要求。框架层可在授权设备内再选一个子集，不能越过宿主策略扩大访问。
- `gpuVisibility` 显示运行环境声明的框架设备范围；可枚举的物理设备可能更多，按已声明范围规划。环境变量用于选择设备，不能据此宣称具有系统级隔离。

先验证正确性与可执行性，再考虑扩大规模。资源不足时如实保存已完成工作和未执行项；不要把 CPU 回退、缩小实验或合成数据替换写成原计划已经完成。review 模式对改变研究目标或关键验证规模的调整提供选项；auto 模式继续独立可做的工作并披露限制。

脚本目前在 Linux 上读取 NVIDIA 的身份/显存/利用率，以及 AMD/Intel render 设备线索；可读的 cgroup v2 文件提供部分配额。其他平台、驱动和框架需要按实际工具补充核实。所有值只代表当前进程可观察的范围。
