默认用**简体中文**写题名、摘要、正文、图表说明与结论，套用技能内的 **ICML2026 双栏模板**。保留英文术语、文献原题名、引用键与数学符号。用户明确要求英文或其他交付格式时遵循用户要求；简短问答或简报不必强行扩写成完整论文。

主会话控制论点、提纲与整合。Pi 自己完成写作；本技能的 Python 代码只生成提示词、组装文档、复制模板、检查与编译，不启动模型或调用外部 API。所有所需提示词、代码与模板都在本目录，不依赖 `temp/` 或原研究框架。

材料发现的根目录是 Pi 运行时提供的会话工作目录（cwd）；本包子任务继承项目根目录。目录由启动位置或调用方配置决定，模型在其中判断材料的相关性，不自行更换项目根目录。报告输出目录与材料根目录分开，编译在报告目录中执行。

## 从材料到报告

1. **自主发现材料。** 默认从 Pi 当前工作目录及其相关子目录查看文件，由模型根据研究主题、内容和来源关系自行判断哪些 Markdown、JSON、文献、运行记录、指标和图表有用。不要求用户显式指定输入文件或事先提供文件清单，也不依赖固定名称的目标、假说或方法文件。先查看目录与候选文件，再按需阅读相关内容、追踪其中的原文和运行产物；不要把所有文件不加筛选地读入上下文。用户明确限定材料范围时遵循该范围；子任务同时遵守运行时的访问边界。优先读取关键原文与指标，不只依赖摘要。区分事实、推断、建议、方案与已完成实验，保留反证、负结果、局限和未完成部分。缺少实验时写成综述、方案或阶段报告；只有自主查找后仍有影响报告成立的关键缺口时才向用户询问。
2. **准备写作目录。** 主会话默认输出到项目 `paper/`；有用户指定目录则使用该目录。被 `research_delegate` 调用时必须用**分配的输出目录下的 `paper/`**，包括命令、日志与编译缓存。不要在已安装技能目录内写报告，不覆盖共享状态。已有报告先检查再续写，`init` 只适用于新目录。
3. **规划和撰写。** 阅读 [写作流程与上下文](references/writing.md)。由模型把自行筛选并读取的材料整理为 `context.json` 和 `evidence.md`，再使用技能内提示词依次形成 `outline.json`、题名/摘要/关键词、章节正文。这些文件和后续 `report.json` 都是模型在生成过程中创建的内部产物，不要求用户预先准备。提纲按材料调整，不强制六节。写作中就地加入已核验引用，不在完稿后用检索结果装饰已有主张。最后根据全文修订摘要。
4. **组装源文件。** 按 [产物与命令](references/output.md) 填写 `report.json`，运行 `render`；默认选择 `Journal.ICML2026`，生成 `main.tex`，复制必需 `.sty`/`.bst`、章节、参考文献与实际图片。标题、作者等元数据为纯文本，摘要和章节为 LaTeX 正文，避免重复转义。
5. **校验、编译与检查版面。** 运行 `check`，然后 `compile`。中文默认 XeLaTeX + BibTeX + Fandol 字体，也可显式选择 LuaLaTeX；不能用 pdfLaTeX 编译中文。依赖与字体配置见 [README 报告编译环境](../../README.md#报告编译环境)。编译使用 `-jobname=report` 直接生成 `report.pdf`，包括临时构建在内都不生成 `main.pdf`；旧版本留下的重复文件由成功编译流程清理。读取日志，局部修复后重跑，自动修复最多三轮，仍失败就交付源码与明确错误。不得为通过编译删除证据、改动数据或扩大结论。生成 PDF 后，用实际可用的 PDF 读取/渲染能力检查中文、公式、引用和双栏图表；无可用预览工具时明确未做视觉检查。

从任意工作目录调用脚本时，把 `<skill-dir>` 替换为当前 `SKILL.md` 所在目录的**实际绝对路径**，不能假定安装在项目 `package/` 下：

```bash
python3 <skill-dir>/scripts/report_generation.py init --output paper
python3 <skill-dir>/scripts/report_generation.py render --manifest paper/report.json --output paper
python3 <skill-dir>/scripts/report_generation.py check --output paper
python3 <skill-dir>/scripts/report_generation.py compile --output paper
```

`render` 遇到不同内容的已有文件会拒绝覆盖；确认是本次续写需要替换的生成文件后使用 `--force`。已有相同文件可重复运行。`init` 创建的是未完成骨架，不是报告成果；必须写实质正文后才能 `render`。

## 证据与交付边界

不得编造 DOI、作者、单位、通讯邮箱、页码、实验指标、图片或引用。文献只使用已核验的 BibTeX 元数据；缺证时在正文降低断言强度，未解决问题记入证据索引。图表必须关联实际数据、生成脚本和运行编号；无图时不强制插图，不把模板示例文献当成研究来源。

模板默认 `preprint`，表示草稿排版，不声称已获 ICML 录用；`accepted` 仅在用户明确要求时设置。中文适配使用 `ctex`，不改原样式文件、页边距或双栏尺寸；这是中文报告模板，不承诺符合会议的投稿语言和格式要求。

结束时交付成功生成的 **`paper/report.pdf`** 路径，同时提供报告主张与局限、`paper/main.tex`、引用/证据索引、编译状态；不额外交付重复的 `main.pdf`。检查 `build-status.json` 的 `ok`、`report_pdf` 和本次来源摘要；编译失败、依赖缺失或源码已更改时，不把目录中旧 PDF 作为本次成果。结构检查不能替代来源核验或科学评审。需要独立审阅时，可按用户任务使用已有 `research-review` 能力，交付报告和证据实际路径，不要求继承完整写作历史。子任务完成时用运行时提供的 `research_finish` 返回真实成果与缺口。
