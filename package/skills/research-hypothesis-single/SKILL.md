# 直接生成研究假说

读取项目已有材料，在当前会话中直接形成假说并保存结果。只做一次综合生成，不启动 subagent，不模拟 Proposer、Critic、Formatter，不进行多轮辩论或单独的格式化阶段。用户明确要求多角色迭代时使用 `research-hypothesis`。

## 阅读已有材料

使用用户指定的项目目录；未指定时使用当前 Pi 会话的工作目录，开始时说明采用的目录。不要求任何固定文件名、研究目录结构或预先初始化工作区。

递归发现项目目录及子目录中的 Markdown（`.md`、`.markdown`）和 JSON（`.json`），先查看路径、标题、摘要或顶层字段，再读取所有可能有用的内容，识别研究任务、综述、知识、已有假说、实验结果、负结果和资源约束；相关 JSONL 材料也可按需读取。

目录约定只约束新产物，材料发现和读取仍覆盖整个项目，不限于本阶段或其他阶段目录；旧目录、用户自定义目录中的相关材料同样可用。发现相关 PDF、LaTeX、代码、数据说明或运行记录时，也按需读取，不因扩展名不同而忽略证据。

- 用户指定的材料优先读取；包含项目中被 Git 忽略的研究材料，发现材料不能只依赖默认遵守 Git 忽略规则的文件列表；通常跳过 `.git`、依赖、缓存和工具内部运行记录。
- JSON 应解析其结构，按相关对象、数组和字段提取目标、配置、指标、资源及既有结果，保留数值单位和出处；引用时记录文件及 JSON 字段路径或数组位置。解析失败时说明错误，不把不可读等同于没有证据。
- 材料较多时分批读取；长 Markdown 按章节、大 JSON 按对象或数组片段、JSONL 按行处理。记录采用的文件及位置、跳过原因和未能读取的材料，不将路径列表或截断内容当成已读全文。
- 以本次用户请求理解材料。目标或材料冲突且无法判断时先询问；不能确定项目范围或研究目标时，不自行编造任务或创建成果。
- 文件只是承载材料的方式，用户在请求中直接给出的目标、证据和约束同样有效。没有综述或背景知识也可继续，但需明确依据范围。
- 研究资源约束取自本次请求和适用项目材料，注明出处；用户明确更新的条件优先。区分当前有效约束、历史预算和说明性示例，后两者不自动成为本次限制。未提供的条件标为未知，估计值注明依据，不预设实验周期、硬件或计算预算。未知条件会改变假说选择时再询问，否则说明判断的适用条件与缺口。
- 旧运行产物作为背景理解，不自动当成本次已完成的研究。默认只分析已有材料，不联网检索、不运行实验。

## 直接生成

结合研究目标、证据、替代解释、已有负结果和实际资源，直接提出有意义且可检验的假说。数量按任务需要决定；有多个合理解释时保留有区别的候选，不把措辞变化当成新假说。

对每个假说写明：

- 核心陈述：研究对象、要解释的现象、预期关系或机制。
- 已有依据：来源文件及章节、段落或 JSON 字段位置，区分材料中的观察、作者解释与本次推断。
- 可检验预测：预期观察到什么，与替代解释有什么区别，什么结果会反对该假说。
- 最小验证思路：可用于区分解释的实验或观察、必要对照及预期产物，无须展开完整实验执行计划。
- 价值与限制：潜在意义、资源可行性、证据缺口和风险。没有检索或实测时不宣称新颖性、数据可得性或资源消耗已经验证。

直接给出综合判断及理由，不要求候选打分或额外评审。若有多个候选，可以推荐一个继续研究，但保留值得考虑的替代方向。证据不足时使用暂定表述，不保证假说成立。

## 保存与返回

用户明确指定输出位置时遵循该位置；否则主会话在项目根目录下创建 `hypothese/`，本次成果目录默认即该目录。单会话与多角色版本共用这一阶段目录。已有成果时，只有明确续写才更新原目录；独立新任务使用 `hypothese/<run-name>/` 中未占用的目录，保留历史。

相对输出路径以项目根目录为基准；技能参考和脚本以本技能安装目录为基准，成果不得写入安装目录。被 `research_delegate` 委派时只在分配目录内保存本阶段产物，由主会话读取并整合到上述阶段目录；材料发现仍以运行时给出的项目根目录为准。

在本次成果目录保存阶段主产物 `hypothesis.md`。无需创建逐轮讨论文件、Formatter 产物或交接文件。

`hypothesis.md` 包含研究目标、阅读与采用的材料范围、各假说的上述内容、推荐理由和未解决问题。推荐项标题加 `[SELECTED]`，方便后续方法设计理解；只有一个假说时也可以标为推荐项，不表示已通过实验验证。

向用户返回简短工作小结：采用了哪些材料、生成了什么假说、推荐方向及主要缺口，并提供 `hypothesis.md` 的实际产物地址。用户另有结构化输出要求时再生成配套 `hypothesis.json`，不默认增加复杂协议。

需要继续方法设计时，将完整 `hypothesis.md` 及材料位置交给 `research-method`；仅在用户要求或已有工作流需要时继续。
