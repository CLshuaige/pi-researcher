# 运行与恢复

## 方法输入

优先使用调用方明确提供的方法文件，默认文件名为 `method.md`。按实际内容理解目标、约束和验收条件。检查历史代码和数据仍存在且适用于当前方法。

## 捕获真实运行

从工作区根目录运行，以下 `<skill-dir>` 替换为 Pi 提供的本 Skill 安装路径：

```bash
node <skill-dir>/scripts/run-capture.mjs \
  --cwd . \
  -- node --version

node <skill-dir>/scripts/verify-run.mjs \
  --run experiment/runs/<返回的北京时间戳>
```

省略 `--output` 时，脚本自动创建 `experiment/runs/YYYYMMDD_HHmmss_SSS/`，并在输出的 `RUN_CAPTURE` JSON 中返回 `run` 路径。目录名使用运行开始时的北京时间（UTC+8）。需要指定目录时也使用这一时间戳约定；目录已存在时等待下一个时间戳，不覆盖或改用顺序编号。

`--` 后是实际程序和独立参数；包装器不自动作 shell 展开。输出目录必须在当前工作区内且尚不存在。`stdout.log`、`stderr.log` 和 `run.json` 保存原始输出、命令、cwd、时间、退出码和终止信号。程序失败时包装器也返回失败状态。

凭据通过运行进程环境提供，不能放进会被记录的命令参数。检查程序日志不要意外输出凭据。

集群或远程任务可使用既有调度器记录，保存作业 ID 和真实终态。进程成功退出仅说明执行结束，还需检查数据、指标和科研结论。

分别报告日志完整性与进程执行状态：`logsPresent` 表示记录是否存在，`processSucceeded` 表示实际进程是否成功。失败运行也可以有完整日志；它的失败退出码及状态应如实保留。

## 中断后继续

- 保留既有日志、报告和 checkpoint；新的执行使用新的运行目录。
- 先读先前 `result.md`、run.json 和原始记录，识别已完成、失败和未执行的工作，避免重复昂贵计算。
- 复用既有代码、数据或 checkpoint 时记录来源和版本，不覆盖原始证据。
- 报告分别说明历史结果与本轮实际执行。目标或方法改变时重新判断原结果适用性。
- 向主会话交接当前状态、成果路径及继续所需条件，由主流程管理恢复入口。

如果程序自动回退到合成或示例数据，必须核实并在结果中说明。原目标要求真实数据时，不能将这种运行报告为已完成目标。
