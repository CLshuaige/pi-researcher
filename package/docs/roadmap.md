# 后续可选增量

以下是可选择的后续工作，均不阻塞当前 TUI package 使用。按实际任务暴露的瓶颈选择，不按表格顺序机械实现。

| 增量 | 触发条件 | 建议实现 | 验收方式 |
|---|---|---|---|
| 文献服务接入 | 本地材料无法覆盖研究问题 | 配置一个搜索/全文服务；保留 DOI、原文位置和抓取结果 | 固定问题能定位支持与反对证据；缺少全文时诚实报告 |
| 结构化运行记录 | Agent 经常遗漏命令、参数或数据版本 | 为 engine 增加确定性的 run-command 工具和领域指标解析器 | 每次运行关联命令、代码版本、数据、退出码及指标；失败也保留 |
| 更强的证据校验 | 报告引用漂移或摘要传递失真 | 来源去重、引用定位校验；关键论点独立核查 | 抽查可回溯到原文或原始运行；无虚构引用 |
| 持续后台实验 | TUI 关闭后必须继续计算 | 复用成熟 runner/进程管理器，增加作业 ID、心跳、终态与重连 | 断开并重启 TUI 不重复启动同一实验，能停止真实进程树 |
| 跨进程资源预算 | 多个 Pi 会话争用 GPU 或并发额度 | 项目级资源租约，区分模型调用和实验执行 | 并发竞争不超额，死进程租约能可靠回收 |
| 隔离执行目录 | 多实验并行改动同一代码库 | 每个实验 worktree 或容器，记录基线和输出 | 无并发覆盖；产物与原始代码版本对应 |
| 更灵活的续接配置 | 任务需要中途更换工具或模型 | 显式新会话接力协议，而非篡改旧会话合同 | 交接清楚记录变化，旧成果仍可审计 |
| 跨项目经验复用 | 重复研究经常重新发现相同经验 | 先做人工可审阅的经验文件，再考虑索引 | 经验有来源和适用条件，不把未证实假设变成永久规则 |
| 实验方向搜索 | 单一路径常陷入低价值迭代 | 在现有成果上增加候选比较与有预算的分支探索 | 相同总预算下与单路径基线比较，保留负结果 |

## 研究质量评估

在自己的模型与资源上选择至少三类任务：短文献核查、已有数据的分析、带失败和恢复的实验。比较主会话直接执行与按需委派，不以调用了多少模块作为成功标准。

记录总耗时、模型使用量、重复工作、关键引用可核查率、实验可复现性、恢复后是否重复执行，以及人工修正次数。先根据这些证据调整 Skills 和任务粒度，再决定是否增加基础设施。

第一版明确没有后台存活、全局 GPU 调度、自动向量记忆库或强沙箱。它已经具备七类能力、独立/续接会话、文件交接、TUI 管理和 engine 接入；上述增强改变的是服务范围，不是补齐一个不可用骨架。
